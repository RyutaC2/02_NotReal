# 要件定義書

## 1. プロダクト目的

- 何のために作るのか
  - 技術的側面
    - フロントとバックを実装しデプロイすることで、フルスタックの全体的な技術を会得するため。
    - ログインやフォロー/フォロワー、外部api利用の基本的な技術を使ったアプリケーションを開発し学習するため。
    - フォロー/フォロワーなどの複雑なDB設計を学習するため。
    - AWSにデプロイし、公開することで、AWSやDockerなどインフラに近い領域の学習をするため。
  - 意図的側面
    - SNSで「リアル」を共有するBeRealとは逆に、投稿がAIによって強制的に非現実な画像に変換されることで、「本当の自分」ではなく「盛られた自分」「虚構の自分」を演出し、現代のSNS文化を皮肉る。
    - SNS依存や他人基準での自己評価、承認欲求に振り回される現代の若者やSNSヘビーユーザーに対し、SNSの本質や使い方を考えるきっかけを提供するため。
    - AIの進化により自身の生活に今後どのような影響が出るかを考えさせるため。
    - 投稿する人だけではなく、SNSを見ている人も、偽られた、一瞬の最大風速だけが切り抜かれた他人の華やかしい投稿を見ているということに気づかせるきっかけを作る。

- どんな課題を解決するのか
  - コミュニケーションツールであるはずのSNSが、結局は「盛る」ことや「着飾る」ことに終始してしまう現代のSNS文化を風刺・皮肉る。
  - 「楽しむ」ためではなく、「見せる」ためのSNS利用やその生活に対する問題提訴。

- 成功状態
  - 主要機能を実装し公開・デプロイできていること。
  - AIによる画像編集が正常に動作し、ユーザーが「NotReal」な投稿を体験できること。
  - 皮肉や風刺の意図が伝わるUI/UXになっていること。（元のBeRealの基本的なデザインは変えない。）
    - BeRealでいう外カメが編集後画像、内カメがオリジナル画像として表示し、対比する。
    - BeRealでは投稿をすべて見終わると「現実に戻る時間です。」的なメッセージが表示される。ここにユーザーに向けた問いを表示させる。

## 2. ターゲットユーザー

- 年齢・属性
  - Z世代やα世代などを中心とした、SNSを日常的に利用し、自己表現や他者からの評価に敏感な層。
  - SNSで「リアル」や「映え」を意識するユーザー。
  - SNS依存傾向のあるユーザーや、承認欲求・自己演出に関心がある人。
  - 他人の投稿や成功者の投稿を見て、自分と比較してしまったことがある人。

- 利用シチュエーション
  - 「NotReal」の名前が気になって使ってみるとき。
  - SNSの「リアル」と「虚構」の境界を楽しみたい、または考えたいとき。

## 3. ユースケース

- ユーザーが日常の写真を投稿すると、自動的にAIによって非現実的な画像に変換され、SNS上にシェアされる。
- 他のユーザーの「NotReal」な投稿を見て、SNSの「リアル」とは何かを考えるきっかけになる。
- 「盛る」「着飾る」ことを逆手に取り、あえて非現実的な自分を演出して楽しむ。
- SNSの承認欲求や自己演出に対する皮肉や風刺を、体験を通じて感じる。

## 5. 非機能要件

- パフォーマンス
  - レスポンスタイム：画面遷移2秒以内
  - 投稿反映タイム：25秒以内
  - 画像アップロード上限：10MB/1枚
- セキュリティ
  - 認証方式：JWTによるステートレス認証（有効期限あり）
    - 認証エンドポイント（/login, /register）: 10req/分/IP
    - 投稿エンドポイント（/posts）: 5req/分/ユーザー
    - AI変換エンドポイント: 3req/分/ユーザー（コスト対策も兼ねる）
  - パスワード：bcryptによるハッシュ化
  - 画像アップロード：MIMEタイプ検証・サイズ制限をサーバーサイドで実施
  - CORS：フロントエンドのオリジンのみ許可
  - HTTPS通信のみ許可（HTTP→HTTPSリダイレクト）
- 可用性
  - 稼働率：特に規定しない（個人ポートフォリオのため）
  - 障害時：エラーページを表示し、ユーザーへ状態を通知する
- 保守性・開発品質
  - APIスキーマ：OpenAPI (Swagger) で定義・管理
  - ログ：エラーログはCloudWatch Logsに出力
  - リントツール：ESLint/Prettier（フロント）、golangci-lint（バック）

## 6. AI画像変換フロー

1. マルチモーダルAIを利用して画像を分析し、内容を改変するプロンプトを生成させる。
2. 画像生成AIを利用して内容を改変するプロンプトで画像を再生成させる。（image2image）

- 投稿ボタンを押してから画像が生成され反映されるまで15秒~30秒と試算。この間はスピナーなどで数秒待たせたあと、SNS依存の啓発メッセージを数秒表示させたりして時間を稼ぐ。
- 1で渡すプロンプトは開発を進めるうえで固めていく。

  - フォーム・バリデーション：React Hook Form + Zod
  - HTTPクライアント：Axios
- バックエンド

  - フレームワーク：Echo

  - 認証：JWT
  - バリデーション：go-playground/validator

  - PostgreSQL
  - マイグレーション：golang-migrate
